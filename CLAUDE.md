# LeoChess — інструкції для Claude Code

Шаховий тренажер для дітей і юнаків (перший користувач — донька автора; далі — додаток для ДЮСШ).
Уся сторінка — **один самодостатній HTML-файл** без сервера: дані, фігури, chess.js і Stockfish вбудовані.
Автор не програміст: пояснюй зміни просто, українською, і завжди перевіряй результат тестами.

## Мова й стиль

- Інтерфейс, коментарі до ходів, плани, README — **українською**. Код і назви змінних — англійською.
- Шахові ходи — латинська нотація SAN (`Nf3`, `O-O`, `Bxf7+`), чорні ходи з трикрапкою: `10…h6`.
- Лапки «ялинки», тире —. Коментарі до ходів короткі (1–2 речення), пояснюють *навіщо* хід.
- Мобільна версія — головна: перевіряй ширину 390 px, жодного горизонтального прокручування.

## Збирання

```bash
pip install -r requirements.txt
python3 scripts/build.py          # дані + фігури + сторінка → dist/index.html
python3 scripts/build.py --page   # лише перезібрати сторінку після правок у src/
```

`dist/` і `build/` генеруються — **не редагуй їх вручну** і не коміть (є в `.gitignore`).
`src/index.html` містить плейсхолдери, які підставляє `scripts/build.py`:
`<!-- @@ICONS@@ -->`, `<!-- @@COACH@@ -->`, `/* @@STYLES@@ */`, `/* @@SF19@@ */`, `/* @@SF10@@ */`, `/* @@PIECESETS@@ */`, `/* @@CHESSJS@@ */`,
`/* @@APP@@ */`, `/* @@PIECES@@ */`; у `src/app.js` — `/* @@DATA@@ */`.

## Як влаштований `src/app.js`

- `DATA` — розділи → лінії. Лінія: `id, name, side, plan{w,b}, san[], uci[], fen[], com{ply: текст}`, опційно `mg`.
- `S` — увесь стан: `op` (розділ), `ln` (лінія), `ply`, `mode` (`view` | `train` | `mg` | `an`), `side`, `flip`, `sel`…
- Вибір ліній — «бібліотека» `#lib`: на ширині ≥1180 px це бічна панель, вужче — шторка (`openSheet('lib')`),
  яку відкриває рядок поточної лінії `#lineBar` (стрілки `stepLine(±1)`). `S.lib` — розділ, відкритий у бібліотеці
  (вкладка розділу одразу відкриває його останню лінію — `S.lastLn`, щоб підсвічений розділ завжди збігався з дошкою; картка обирає конкретну лінію). Налаштування вигляду — шторка `#settings`, плитки фігур і дошок.
  У тестах лінію обирай через `pick(pg, розділ, лінія)` з `tests/conftest_helpers.py`.
- Рендер: `render()` → `renderTabs` (бібліотека, прогрес у шапці, рядок лінії), `renderBoard` (поля) + `renderPieces` (фігури окремим шаром, плавна анімація),
  `renderMoves`, `renderInfo`, `engPanel`.
- Режими: перегляд — `go()`, `viewMsg()`; тренування — `startTrain`, `tap`, `afterMove`, `finish`;
  мітельшпіль — `startMg`, `mgNext`, `mgTap`, `mgFinish`; аналіз — `startAn`, `anTap`, `anGo`, дерево `S.an.nodes`.
  Відкладені ходи (`S.oppT`, `S.mgT`, `S.flashT`) скасовує `stopTimers()` — викликай його при кожній зміні лінії чи режиму.
- `Coach` — реакції леопарда (лише міміка, без тексту): `view`, `mine`, `opp`, `wrong`, `hint`, `finish`.
  **Зараз вимкнений** на прохання автора (`COACH_ON = false`, `#coach` прихований, перемикач у «Вигляді» прибрано);
  щоб повернути — `COACH_ON = true` і рядок `#optCoach` у шторці налаштувань.
- `Eng` — Stockfish у Web Worker з черги запитів; `req(fen, foreground)`, кеш оцінок, `deep()`.
  Спершу запускається Stockfish 19 lite, при збої — Stockfish 10. `moveMark` ставить `?!`/`?`/`??`
  за зміною шансів на виграш (як на Lichess), `explain` будує пояснення з варіантів рушія.
- `Raster` — тематичні фігури лежать у сторінці як JSON із сирими SVG (`#pieceSets`) і стають CSS лише для
  обраного набору: спершу вектором, потім фоном, по одній фігурі, перемальовуються в PNG (вектор із візерунками,
  особливо «Самоцвіти», браузер перемальовує на кожному кадрі — гальмувало). Нові теми підхоплюються самі (`PIECES`).
- `Eng.flavour()` — `wasm` (Stockfish 19) | `asm` (запасний Stockfish 10) | `none`.
- **Гра з комп'ютером** — режим `play` (кнопка «Грати» в шапці → шторка `#play`; `S.pl` — партія: `g` (chess.js),
  `ucis`, `sans`, `side`, `level`, `fen0`, `over`). `Bot` — окремий воркер Stockfish (кеш аналізу не чіпає), черга
  без накладань, `Bot.move(fen, level)`, `Bot.best(fen)` для підказки, `Bot.cancel()`. Рівні `LEVELS` 1–8: обмежена
  глибина + кілька кандидатів (MultiPV) + зважений випадковий вибір (температура `T`) + інколи випадковий хід (`rnd`);
  9 — повна сила. UCI_Elo самого Stockfish навмисно не використовуємо: при швидких ходах він слабший і непослідовний.
  Змінив параметри рівня — перевір порядок сили матчами бот проти бота (сусідні рівні, по 6 партій зі зміною кольорів).
  Після кожного ходу партія зберігається (`openingTrainerPlay`: `game`, `stats` по рівнях, останні `level/side/from`).
  Вихід з гри (інший режим чи лінія) — `leavePlay()`: скасовує думку бота; партію можна продовжити.
  Дебют комп'ютера (`P.book = {sec, line}`, шторка «Дебют комп'ютера»): з початкової позиції бот ходить за лініями
  розділу (`bookLines` = лінія + продовження мітельшпілю, якщо воно не з власної позиції), поки партія збігається
  з ними (`bookNext`); ходи з позначкою `?`/`??` за книгою не грає. Учень зійшов з теорії — `P.note` пояснює, що
  грають у лініях; підказка в книзі показує теоретичний хід. Розділи «Партії Морфі» й «Мініатюри» в книгу не входять.
- **Задачі** — режим `puz` (кнопка «Задачі» в шапці → шторка `#puz`; `S.pz` — задача: `g`, `sol`, `i`, `side`, `ucis`,
  `sans`, `failed`, `hinted`, `done`). Беруться **онлайн** з Lichess: `GET lichess.org/api/puzzle/next?difficulty=…&angle=…`
  і `/api/puzzle/daily` (без входу, CORS дозволено; складність відносно 1500 для анонімів, рейтинги в `PUZ_DIFF` заміряні).
  Запити по одному (`puzQueue`), наступна задача підвантажується заздалегідь (`prefetchPuz`). Позиція — партія з PGN без
  останнього ходу; останній хід (суперника) показується першим. Будь-який матуючий хід зараховується, як на Lichess.
  Без інтернету — зрозуміле повідомлення. Теми задач перекладає `THEME_UA` (невідомі не показуються).
- localStorage (усе в try/catch): `openingTrainer` — прогрес, `openingTrainerStyle` — тема/дошка/тренер/рушій,
  `openingTrainerAn` — варіанти аналізу по лініях, `openingTrainerPlay` — гра з комп'ютером, `openingTrainerPuzzles` — статистика задач і вибрані налаштування. Ключі не перейменовуй — у користувачів збережений прогрес.

## Як додати контент

**Дебютна лінія** — у `data/openings.py`, у потрібний розділ:

```python
{"id": "ita-new", "name": "Назва", "side": "w",
 "moves": "e4 e5 Nf3 Nc6 Bc4 {Коментар після ходу.} Bc5 c3 ...",
 "plan": {"w": "План білих…", "b": "План чорних…"}},
```

Коментар у `{…}` прив'язується до ходу перед ним. `!`/`?` після ходу зберігаються як позначки.

**Мітельшпіль** — у `data/middlegame.py`, ключ = id лінії. Кроки: `('t', хід, [альтернативи], питання, пояснення)` —
завдання для учня; `('o', хід, коментар)` — відповідь суперника; `('a', хід, коментар)` — хід учня автоматично.

**Партія** — у `data/morphy.py` / `data/miniatures.py`, той самий формат, що й лінія; `side` — сторона, за яку грає учень.

## Обов'язкові перевірки контенту

1. `python3 scripts/build.py` — зупиниться на нелегальному ході з id лінії й номером ходу.
2. Шахова правдивість: кожен новий хід і кожну альтернативу в завданнях перевір рушієм
   (`tools/check_middlegame.py`, `tools/audit_lines.py`). Помилки в лініях позначай у коментарях чесно (`?`, «сильніше було…»).
3. Історичні партії — звіряй ходи з базою (Lichess, chessgames) і вкажи джерело в коментарі коміту.
4. `tests/run_all.sh` — тренування всіх ліній, мітельшпіль, аналіз, інтерфейс (`test_ui.py`), гра з комп'ютером (`test_play.py`),
   задачі (`test_puzzles.py` — Lichess підмінено збереженими задачами з `tests/fixtures/`, інтернет не потрібен); після змін у `src/` — обов'язково.

## Швидкодія (важливо для анімацій)

- Анімуй лише `transform` і `opacity`; не міняй `top/left/width/height` у русі.
- Дошка не перебудовується: 64 клітинки створюються раз (`buildSquares`, повторно лише при перевороті),
  рендер лише міняє класи. Фігури — окремий шар (`renderPieces`), кожна рухається `transform`.
- `renderTabs`, `renderMoves`, `renderInfo` перемальовують лише те, що змінилося (ключі `libKey`, `movesKey`,
  `infoKey`); закрита шторка бібліотеки не будується, доки її не відкриють.
- Не вставляй великі векторні картинки прямо як фон рухомих елементів — малюй їх у PNG (як `Raster`).
- Поважай `prefers-reduced-motion` (блок у кінці `styles.css`).

## Обмеження

- Сторінка має лишатися одним файлом (її також публікують як артефакт і на GitHub Pages): без зовнішніх
  запитів, усе вбудоване. **Єдиний виняток — задачі з Lichess** (на прохання автора): решта додатка працює офлайн,
  а задачі без інтернету показують повідомлення. Нових зовнішніх запитів без потреби не додавай. Нові бібліотеки — у `vendor/` і через плейсхолдер у `build.py`.
- `build.py` патчить завантажувач Stockfish 19 (хук `instantiateWasm`): wasm вбудований стиснутим (gzip+base64,
  2,4 → 1,6 МБ) і розпаковується у воркері через `DecompressionStream`; де його немає — вмикається Stockfish 10
  (його навмисно не стискаємо — він саме для старих браузерів). `test_ui.py` перевіряє, що стартує саме Stockfish 19.
  При оновленні Stockfish перевір, що хук знаходиться (інакше build зупиниться з поясненням).
- Ліцензія GPL v3 через Stockfish — рядок про авторів унизу сторінки не прибирай.
